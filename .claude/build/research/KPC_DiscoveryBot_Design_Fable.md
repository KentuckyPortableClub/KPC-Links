## 0. The idea in one paragraph
We already have five small explorers that each look in one place in one way. They miss because they look by fixed names and fixed servers. The Discovery Bot is one script that asks the CATALOGS (where agencies list everything they publish) by keyword, then tests every new lead with the explorers we already have, grades it automatically, and writes one ranked file of "things worth adding", biggest payoff first. It never adds anything to the live data itself, never emails, never fails. People (chat 8, Brandon) only read the top of the list.

## 1. RULE SHEET: DISCOVERY LEADS (RULES FIRST)
**(1) What counts as a lead.** A dataset, map service, layer, page or feed that (a) is published by the managing agency, the state/province GIS office, or a national register (PAD-US, CPCAD, NHD, Census), (b) we do not read yet (its URL is not in `state-gis.json`, `us-key/layers.json`, `ca-key/layers.json`, `access-layers.json`, `campstate-layers.json`, `data/trails/index*.json`, `kpc-ky-data.json` links, KYLIVE), and (c) would fill one of the six gaps: park outlines, ownership/public access, official map pages, closures feeds, parking/access points, Canada roads and water.
**(2) What does not count.** Anything from a non-agency host (OpenStreetMap, Wikipedia, tourism and camping sites, app stores, third-party mirrors such as the supabase "park-maps" bucket, university theses, a county's copy of a state layer unless the state has none); city/council park layers (house rule); historic markers; a layer whose licence forbids republishing (WDPA, DAERA Northern Ireland, anything "no derivatives" or "internal use"); planning or theme layers that only NAME a park (hunting units, fire districts, census places); a dataset older than 10 years unless it is the only one.
**(3) Sources, best first.** (a) the state's or province's open-data portal catalog API; (b) the agency's own ArcGIS Online organisation (search by org id); (c) the agency's park pages' "Maps" tab (headless browser); (d) national registers; (e) a web search is NOT a source for the bot (only people do that).
**(4) When unsure.** A lead is listed, never used. The bot never writes into the live data files; it writes leads + an automatic grade and stops. A lead whose service does not answer twice in a month is "sleeping" (kept, not retested for 60 days). A lead whose licence field is missing is "licence unknown" and sorted below "licence ok".
**(5) Grades (automatic, 0-6) and what people see.** +1 service answers and lists layers; +1 has a polygon (or point/line for access/trail/road/water) layer with a readable name field; +1 publisher host is an agency/state domain or a known agency AGOL org; +1 licence stated and open (CC-BY, OGL, public domain, "no restrictions"); +1 it names at least one park we lack (the existing lead tester's count, near the POTA pin); +1 it names 5 or more. **A (5-6)** = chat 8 looks this week; **B (3-4)** = next monthly round; **C (0-2)** = kept in the file, nobody looks. People see `data/portal-leads.json` and a 10-line count in the boundary-check issue BODY (an edit, no email). Chat 8 still gives the human A/B/C on the leads it opens; the bot's number is the queue order only.
**(6) Examples incl. the hard ones.** (a) Kentucky "Kentucky Wild Rivers (Corridors)" on opengisdata.ky.gov: found by keyword "wild river", publisher state, polygon, open, names 9 parks we had only as lines = A. (b) Kentucky State Parks "Maps" tab on parks.ky.gov, filled by script: found only by the headless step; PDFs on kentuckytourism.com = official because the agency page links them = A for the map-page gap. (c) Ohio "ODNR Lands Public nolakes" = already read (in layers.json) = not a lead, dropped. (d) A county GIS "Parks" layer in Utah that holds 3 BLM recreation areas we lack = C (host not the managing agency), listed under "possible second witness". (e) The supabase park-maps bucket = not a lead (rule 2). (f) WDPA on Protected Planet = not a lead (licence). (g) Michigan DNR "project boundaries" = a lead for the OUTLINE gap but tagged "acquisition/project line: not land" so the ownership gap is still open. (h) USFS Basic Ownership (2015 content): already read; its NEWER sibling if one appears (publication date newer) = A, kind "replaces". (i) Natural Resources Canada National Road Network on open.canada.ca: CKAN record with no live service, only downloads = B, kind "download, needs a loader". (j) A Socrata table of campground reservations with lat/lon but no polygon = lead for ACCESS, not for OUTLINE.

Grey areas for Brandon: **D-1** county GIS layers as a second witness only (rec: yes, never as the park outline); **D-2** a layer with no licence text on a .gov host (rec: treat as open for reading, but say "licence unknown" until chat 8 checks); **D-3** headless-browser scope (rec: agency domains in an allow list only, 1 page per 3 s, max 300 pages a month); **D-4** should the bot test world catalogs (rec: not in round 1; US + Canada first).

## 2. THE BOT: `kpc_discovery.py` (one script, one JSON, one workflow step)
**Inputs.** `data/discovery/keywords.json` (the keyword list per gap, grows by hand: every miss a person finds adds a keyword or a URL pattern); `data/discovery/portals.json` (per state/province: the Hub/Socrata/CKAN base URLs and the agency AGOL org ids: the first run seeds it from `state-gis.json` hosts and a hand list, and the bot fills gaps by trying the common patterns `data.<state>.gov`, `gis.<state>.gov`, `<state>.opendata.arcgis.com`, `data.<state>.ca`); the "already read" URL set built at run time from the files in rule (1b); the missing-park lists from `boundary-score.json` (`no_outline` per state) and the keys' `none`/`check` lists; the activity order (HQ's top-10 list; until then parks-per-state).
**Step A: catalog search (cheap, the core).** For each state/province in activity order, for each gap, for each keyword: (1) **ArcGIS Online search** `https://www.arcgis.com/sharing/rest/search?f=json&num=100&q=<keyword> AND (orgid:<agency org> OR owner:<agency user>) AND type:"Feature Service"` (public, no key; the surest single endpoint; org ids come from `state-gis.json` AGOL hosts `services*.arcgis.com/<orgid>`); (2) **ArcGIS Hub** site search `https://<hub>/api/search/v1?q=<keyword>` (or the Hub v3 datasets API) when the state runs a Hub; (3) **Socrata Discovery** `https://api.us.socrata.com/api/catalog/v1?domains=<portal>&q=<keyword>&only=datasets,maps`; (4) **CKAN** `https://<portal>/api/3/action/package_search?q=<keyword>&rows=100` (data.gov, open.canada.ca, data.ontario.ca, catalogue.data.gov.bc.ca, open.alberta.ca, donneesquebec.ca are all CKAN); (5) national registers once per run: PAD-US version page, CPCAD, NHD, USGS NLCS, NRCan NRN/NHN records, NPS Data Store API. Every hit is normalised to {title, publisher, host, url(s) of services/downloads, licence text, modified date, geometry if given, which gap, which keyword, state}. Dedupe by service URL. Drop "already read". Cost: a few thousand small JSON calls a month; 1 request/second per host, 20 s timeout, 2 retries, then "sleeping".
**Step B: automatic test (reuse what exists).** For each new lead with a service URL: the `kpc_test_leads.py` probe (answers? layers? geometry? name field? count? three sample names) then, for outline leads, `kpc_outline_lead_test.py`'s count of missing parks named in it near the pin; for access leads, `kpc_parking_explorer.py`'s point-layer check; for road/water leads a geometry + extent check only. Move those three into a shared `kpc_leadtest.py` so the discovery bot imports them instead of copying. Each test is bounded: `returnCountOnly`, then at most 3 name queries per missing park, attributes only, no geometry downloads. Download-only leads (CKAN zips) are NOT fetched; they are listed as "download, needs a loader".
**Step C: the "Maps" tab (optional, allow-listed, slow).** Playwright (already on the runner). Inputs: `data/discovery/maps-tab.json` = per agency the park-page URL pattern (from `KPC_OfficialMaps_States_desk.md`), the CSS/text to look for ("Maps", "Trail map", "Park map", "Download"), the allowed file hosts. For each park in our data that still has no official map link (the `off` field or `parkinfo-web.json`), open its agency page, wait for scripts, collect `<a href>` whose text or path says map/pdf/geopdf, keep only allowed hosts, write to the leads file as gap "map page" with grade. Limits: agencies in the allow list only, 1 page per 3 s, 300 pages per run, 45 minutes max, skip a host after 5 errors, obey robots.txt, a real User-Agent naming the club. Never fills a page form, never logs in.
**Step D: output.** `data/discovery/leads.json` = {run date, per state: [lead {…, grade, tested, kind: replaces | new | download | map page | second witness, sleeping_until}]}, sorted by state activity then grade then parks-named count, plus `data/discovery/leads.md` (people-readable top 50). One observation per NEW A-grade lead in `data/map-observations.json` (kind "portal lead"). The boundary-check issue BODY gets a 10-line count (edited, not commented). No email: the step ends `|| true`, prints `::notice` lines, and runs inside the existing boundary-check workflow (one more step) rather than a new workflow, so no new scheduled email trigger exists.
**Schedule.** Monthly, the 1st, inside `kpc-boundary-check.yml` (300-min job): step A ≤ 40 min, step B ≤ 60 min, step C ≤ 45 min, each with its own MINUTES budget so one slow catalog cannot eat the run (the split-budget lesson from the 2-fer review). A manual `workflow_dispatch` input `STATES=OH` for tests. A second, quick weekly pass only re-tests "A, untested" leads (5 min).
**Memory and time on GitHub.** ubuntu-latest, ~7 GB: the bot keeps only JSON summaries (no geometry), streams catalog pages (100 per call, max 10 pages per keyword), writes the leads file every 10 minutes so a timeout loses nothing, and the "sleeping" list stops it re-hitting dead servers. Expected: a few thousand requests, well under 2 hours.
**Learning loop (Brandon's point c).** `keywords.json` has `{keyword, gap, added_by, date, found_by_it: [urls]}`; when a person finds a miss by hand they add the keyword (or a URL pattern) and the next run reports what it newly found with it. A keyword that finds nothing in 6 months is marked idle (kept).
**What the bot never does.** Add a layer to the live data; change an answer key; grade A/B/C for people (it ranks, chat 8 grades); fetch geometries; follow links off agency hosts; retry a 403 (GDOŚ, DAERA); run more than once a month without a dispatch; email.

## 4. TEST PLAN: ONE STATE FIRST
**State: Ohio** (same test state as chat 2's run order; small, has a state ArcGIS Hub, an ODNR AGOL org, Lake Erie, Wayne National Forest, and the abbreviated-name problem; 3 parks with no outline and 93 pin-outside, so the test is about ownership and map pages more than outlines). **Second state: Utah** (333 parks with no outline, BLM everywhere: the payoff test).
1. **Dry run, no network writes:** `STATES=OH STEPS=A` by dispatch. Check: the portals file resolves Ohio's Hub + ODNR org id; each keyword returns a normalised hit list; "already read" drops the ODNR lands layers we have (`sgoh*` entries); the run ends green with `::notice` counts (hits, new, dropped as already read, dropped as non-agency).
2. **Grade check:** `STEPS=A,B`. Expect ODNR or Ohio GIS leads for ownership (state-owned land, ODOT right of way), access points (ODNR boat ramps, trailheads), closures (ODNR alerts). Chat 8 opens the top 10 by hand and gives A/B/C; compare with the bot's 0-6: the order must agree on at least 7 of 10 or the scoring weights change before any other state runs.
3. **Maps tab:** `STEPS=C STATES=OH` with the allow list = ohiodnr.gov only, 20 parks: expect `dam.assets.ohio.gov/.../parkmaps/<name>parkmap.pdf` links (the agency's own naming standard); check robots, timing (≤ 3 s/page), and that no link off the allow list is kept.
4. **Rerun safety:** run A again the same day: zero new leads (dedupe works), nothing re-fetched that is "sleeping" or already tested.
5. **Cost and limits:** total requests, minutes per step, memory peak printed in the notices; must be under the budgets in section 2 or the budgets are cut, not raised.
6. **Learning loop:** add one keyword by hand ("wild river", from Kentucky) and one URL pattern; the next Ohio run reports what the keyword found.
7. **Then Utah** (payoff), then the 10 busiest states in one monthly run; Canada (QC first) after the roads/water keywords are confirmed on open.canada.ca and donneesquebec.ca.
**Pass/fail for the whole test:** green runs, no email, at least one A-grade lead in Ohio that a person confirms is real and new, and no lead from a non-agency host in the top 20.

## 1. Is the matching approach sound? Where does it join the wrong land?
**Sound.** Name (kind words stripped, spelling variants) AND same kind of place AND near the pin, with a hand list that always wins, is the right shape, and the second-witness score is the right safety net: it grades the outline with evidence that is NOT the pin, so a wrong POTA pin cannot pull a right outline off. The 'keep the last good outline when the read came back short' guard and the golden cases that stop the whole run on one wrong case are both good engineering. The 'check' list (not joined, a person looks) is the right default for doubt.

**Where it still joins the wrong land (ranked by how often it will happen):**
1. **Same name + same kind within 60 km = ALL of them join.** `run()` joins every record whose name and kind fit within 0.6° of the pin (`near(..., .6)`), so two different 'Big Island Wildlife Area's or two 'Deer Creek' state lands 40 km apart become ONE park's outline (a union of two places). The second witness then scores it HIGH (name 2, agency 1, agree 2, pin 2). Fix: when the joined records fall in two separate clusters (bboxes apart by more than the size of either), keep only the cluster that holds or is nearest the pin and send the other to 'check'. `KM._apart` already exists for this.
2. **The 'words' and NAME_JOIN paths.** 'words' (shared main words within 0.1°) and 'same name, different kind + pin inside' are the two soft rules. They are small (6 of 1,159 Ohio records) but they are where 'Lake X WMA' vs 'Lake X State Park' and 'X Reservoir' vs 'X Wildlife Area' slip through. Each soft join should carry its rule in the score (name 1, not 2) so it lands MEDIUM, never HIGH, until a person or a second map confirms it.
3. **Multi-record parks with one wrong record.** B5 says keep every piece, and the key does; but one wrongly named record among ten right ones (a 'tract' of another unit renamed) is invisible: the score takes the BEST name match across records (`max(name_score...)`), not the worst. Fix: score the worst record too; a park whose worst record scores 0 on name goes to the observations log.
4. **Agency-land parks are still the whole outline in the keys.** The 2-fer bot masks national forests, BLM areas, NPS, Corps, FWS and Michigan project lines to owned land (OWNED), but the answer keys, Am I in the Park and the planners still draw and test the whole proclamation / acquisition / project line (B1 says owned land only). Today 'in the park' is said on private inholdings. See section 2.
5. **Lake-surface layers.** 'Water' records join only at the pin (good) but a lake-named WMA whose pin sits on the boat ramp still joins the lake polygon as 'water outline only'; it is then shown dashed as approximate. Fine as long as the 2-fer bot and Am I in the Park treat 'water outline only' as 'no land outline' (the 2-fer bot already keeps 'reviewed-approx' out; 'water outline only' should be in the same bucket).
6. **PAD-US designation records.** Fee + Designation + Easement records of the same unit all join by name. Easements are filtered at use time in the 2-fer bot (`pad_use`) but NOT in the key or in kpc-bounds.js, so an easement polygon can be drawn as park land in the tools. Fix: the key should write the Category with each joined record (it has it) and the tools skip Easement / Proclamation.
7. **Admin units.** `KM.is_admin` stops field offices / ranger districts; 'management unit', 'region', 'zone' of state agencies are not all in the list (Michigan 'Management Unit', Texas 'Ecoregion'). Low frequency; add words as they appear in the observations log.

The key marks the park `owned: 'usfs'|'blm'|'nps'|'usace'|'fws'|'state'` and keeps the outer line as today.
- **Tools:** kpc-bounds.js `usOutline()` returns, for a park with `owned`, the owned pieces as the FILL (label 'official: <agency>-owned land') and the key outline as the faint dashed 'Forest boundary line: not all land inside is public'. `usLandAt()` / Am I in the Park test the owned pieces first; inside the outer line but not the owned land = the B1 message (ruled wording) + nearest owned land (`edge()` already measures distance). gis-overlays.js and the planners draw the same two layers. One flag, one file, no new network calls from the browser (PAD-US / FS queries from the page are slow and rate-limited).
- **Kentucky first:** kpc-bounds.js already draws ky-dbnf.geojson as the outer line; the owned pieces come from the same `kpc_owned.py` run over Kentucky (the 2-fer run already fetches them). Then per state at the next key rebuild, as the rule sheet says.
- **Date caveat built in:** the owned file carries `source: 'FS Basic Ownership (content 2015)'`, and the message says 'not shown as <agency> land on its ownership map (2015): check the official map' (the 6:49 ruling), never 'this is private'.

## 3. What makes outlines drift wrong over time
1. **PAD-US OBJECTIDs are not stable across PAD-US versions.** The keys, overrides.json (146 hand joins by id), the 2-fer bot, kpc-bounds.js and the second witness all name PAD-US land by OBJECTID. When USGS publishes the next PAD-US (4.1 → 4.2), ids are reassigned: hand joins by id silently stop matching, the 'kept last good' guard keeps OLD ids that no longer exist in the service (the tools then fetch nothing), and the second witness loses its by-id records. Fix: store the PAD-US version string with every id (the service's `description` / layer metadata has it) and a name+manager+acres fingerprint per joined record, so a new version re-joins by fingerprint and the id is refreshed; overrides by id get converted to name joins (500 of 646 already are).
2. **The 'keep the last good outline' guard can freeze a wrong outline forever.** A park whose land was in an old read keeps its join when NONE of that land appears in the new read: right for a flaky server, wrong when the agency really deleted or renamed the unit. The guard has no clock. Fix: `kept` carries a date; after 90 days kept-not-reread goes to the observations log ('outline lost') and after 12 months shows 'last confirmed <date>' (B7).
3. **B7 (source date per outline) is not recorded anywhere.** The key files carry no per-outline date (US-OH.json has only counts/note/st); 'updated' is dropped by the write-only-on-change save. So 'outline: <agency>, <date>' and 'last confirmed' cannot be shown. Fix: write `read: YYYY-MM-DD` per park on every real re-read and `src_date` from the layer's edit date / PAD-US version; the save-only-on-change rule must ignore the `read` field when deciding whether the content changed.
4. **Saved copies (cache/us, CA-ALL.json.gz).** The nightly check rebuilds from the saved ~110 m copy ('use' mode) and only tops it up with NEW layers; the records themselves are never refreshed, so an agency's redrawn WMA stays as it was the day the copy was made. The Canada copy is Oct 22. Fix: a monthly 'refresh' rotation (one or two states a night, `GEO_CACHE_MODE=refresh`), and the B3 / G-M5 size test (25% / 500 acres / piece count) run between old and new copy BEFORE the copy is replaced, with the old copy kept until chat 8 approves.
5. **Renamed or moved layers.** state-gis.json / layers.json hold 190 layer URLs with name fields; a service that moves answers 404, and `extra_state()` logs it and goes on, so the park keeps the saved copy (fine) but nothing tells anyone except a line in the log. Fix: the observations 'layer problem' kind already catches 'did not answer'; add 'not found (404)' and a count per layer, and have the portal scout re-find a dead layer by name.
6. **Hand decisions without a reason or date.** overrides.json has `why` but no date or who; a 'reviewed' join made against the Oct 18 outline stays if the agency redraws (B4 says that is right) but nobody is told to re-look (B-G3 says chat 8 re-checks). Fix: `when` on every override; the observations log pairs a size-change on a reviewed park with 'reviewed on <date>' so chat 8 sees both.
7. **Shadow scoring never graduates.** `score_park()` (kpc_match) has run in shadow since Oct 22 and still decides nothing; two matchers drift apart as rules are added to one and not the other. Either read the disagreement counts and switch, or delete the shadow (cost without benefit).

## 5. Rules that contradict themselves
- **A. Section 2 is that build. Until then Am I in the Park contradicts the ruling on every national forest.
- **B. Make B7 the master: the key records `read` + `src_date`; the tools show the warning after 12 months; the 2-fer bot keeps 'saved copy only' out as it does now.
- **C. Rule 1 example (8) 'two park numbers on one outline = an answer-key question, not a 2-fer'** still says the old thing; HQ 10:35 AM retired it ('Same land, two park numbers' is shown). Fix the example text.
- **D. Second-witness 'agree' counts a state layer + PAD-US as two witnesses (score 2)**, but PAD-US's state records ARE the state's layer handed to USGS: for most state parks the two maps are one source. Not a contradiction in the rules, but the HIGH count (10,133) is flattered by it. Honest fix: 'agree 2' only when the second map is a different AGENCY's layer or a different PAD-US version date; the same agency through PAD-US = 1.
- **E. Rule 1 'NEVER a pin alone' vs kpc_match's `only_fit_holding_pin` (PIN_JOIN).** It is OFF in the US and ON in the world key (where names cannot be read). Allowed by the world pre-flight ruling, but the rule sheet should say so in words: 'pin alone joins only where names cannot be read (world), scored LOW, shown approximate'.

# Known 2-fer pairs per state: PROPOSED (chat 8, Oct 29 ~12:30 PM, task 8.6 / G7)
File: `.claude/build/research/known-fers-proposed.json` (format = KPC-Data `data/waiting/known/fers.json`: per state `keys:[{key, alias_ids, pair, kind, names, acres, why}]`, stable key = park numbers + kind + centre rounded). **231 pairs in 49 states (Ohio has none yet), up to 5 per state, a mix of kinds where the state has them.** Kentucky stays as chat 10 has it (19-20 keys).
**How I chose them (so it is NOT circular):** a pair is proposed only when (1) the line has it LIVE ('candidate') AND (2) members actually logged BOTH parks in one session, from POTA's own activation history (pota-pairs `same_session`: same call, same day, identical QSO counts at both parks). Condition 2 comes from a source the 2-fer bot does not write, so a bad file cannot satisfy it by itself. Each key says how many activations back it (examples: Chugach NF x Kenai Mountains-Turnagain Arm NHA 107; Cheaha Resort SP x Talladega NF 133; Ouachita NF x Talimena Scenic Byway 113).
**Grade C — what this is not:** nobody opened the official maps for these 231. A pair that members activate together is not proof the polygons overlap (POTA lets anyone log both). Before the waiting room uses them as hard 'must stay live' answers someone must look at each state's list. Suggested: chat 11 spot-checks 2 per state against the two official outlines (by the bot: pin inside both outlines or an overlap patch over 50 yards) and drops any that fail; the survivors are the known answers.
**Known risks inside the list:** (a) trail pairs (Talimena, Appalachian Trail) are line parks: the 100-ft rule decides, not acres; (b) big heritage areas (Kenai Mountains NHA) overlap a forest by designation, check POTA's own rule; (c) a pair can be live in the line today and still be wrong (the NY and NS wrong joins were live): the activation condition is what separates them.
**How the waiting room uses a known key:** a state file that loses a known key is HELD. So only add keys that are really 2-fers, in small batches, one state at a time; run the replay test after each batch.

## 1. Where they miss, go stale or break silently (ranked by harm)
1. **Park details (hours, fees, facilities) are not read by any bot.** The rule sheet §4 says 'NPS API fees / entrance types; state park pages for Kentucky', but nothing calls the NPS fees endpoint and nothing writes hours or fees anywhere; data/parkinfo rows hold name / website / type / activation / access from POTA only, and kpc-ky-data.json's visitor lines are hand-typed with a file-level date (2026-10-23) and no per-fact date. The KPC Watcher only DIFFS lines with 'hours/fees/closed/$' on Kentucky pages and tells chat 8. So every 'hours' or 'fee' a page shows today is either POTA's text or a hand note with no 'from the agency, <date>' behind it: §4's own PEOPLE SEE rule cannot be met.
2. **State campgrounds: the layer walk matches by NAME across ArcGIS Online and takes non-agency and wrong-kind layers.** Arizona's 7 'state campgrounds' are the historic **US Army border camps** (Camp Naco, Fort Huachuca); Colorado's 23 are **Rocky Mountain NP backcountry sites** (federal, filed as state); California's source is 'AvonPark_CampBlanding' (military bases), Florida's 'Northwest_Region_Goose_Pasture'. The points lie inside the state, so the bbox test passes and the 'none' list looks good (29 states listed, 21 none). The rule sheet §3 NEVER ('a facilities row that is not a camp') is broken by the publisher, not the row: SOURCE must be the agency's own server or account (data/state-gis.json roots only), never an AGOL keyword hit.
3. **Closures cover 10 agencies in 9 states (172 items), and 4 of the 10 feeds return 0 items** (AR, NC, NJ, OR: 'ok' but empty, which is indistinguishable from 'nothing closed'). 41 states have no closure source at all, so every tool's 'check the agency's closures' line is doing the work. The Round-4 worksheet found 136 candidate sources; only the machine-readable ten were built (right per the rules), but the 126 others were never turned into Watcher targets, so a blocked or HTML-only agency is simply absent, not watched.
4. **Map links: 208 of 2,003 fail the link check (95 × 404, 91 × 403) and stay in the file; 1,427 of 1,999 are bot-found; only 206 carry a map date.** The tools hide a failing link (map_check ≠ ok), which is right, but nothing retries, re-finds or lists them for a person: a 404 from an agency redesign is a silent loss of a link that WAS checked once. 403s are mostly robot-blocked PDFs that a browser opens: those should be 'blocked, probably fine', not 'not ok'.
5. **No fact carries its own date except map_check / closures.** Access points (46,902 points, 46 states) have no read date; campstate has a state-level 'updated'; parkinfo rows have none; parkinfo-web has map_date on 10%. B7 for outlines was just built (boundary review #2); the same rule is not applied to any other fact, so 'from the agency, <date>' and 'last confirmed' cannot be shown, and the Watcher cannot tell 'changed' from 'first seen'.
6. **Silent 'last good' everywhere.** Closures, campgrounds (RIDB), parkinfo-web and the keys all keep the previous file when a read fails or comes back short. Right by the rules, but none record HOW LONG it has been kept: a feed dead for a month still shows last month's closures as current. (The observations log now catches outlines kept 90 days; nothing else.)
7. **Watcher routes by chat, not by fact.** It hashes whole lines and reports 'text changed on <page>' to chat 8; chat 8 then has to find what changed and where it lives in our data. Nothing links a changed Kentucky page to the park record, so a changed fee can be reported and still never updated.
8. **Access points by PLACE within 300 m tie a county boat ramp or a highway rest area to the nearest park;** by NAME is safe. 6,596 parks have points; there is no per-point 'how tied' flag in the output, so the Kit shows both the same way. (The rule sheet UNSURE line covers 300 m-1 km; it does not cover 'statewide layer, by place, no agency link'.)
9. **Lead files are five, not one.** map-leads.json (600), access-leads.json/.md, data/outline-leads/near-miss.json, state-camps-probe, state-gis-found.json, plus the observations log: chat 8 has five places to look and none has a 'graded' column, so a lead reviewed once is re-listed next month.
10. **Kentucky park alerts and US closures are two codebases with two rule sets** (two-check rule, overnight hold, two-sources-agree in KY; none of that in kpc_us_closures). When a state feed flickers, kpc-conditions.json flickers with it.

## 2. How they fit the Discovery Bot (one lead list, one review file, one keyword list)
- **Leads:** every 'found but not yet used' thing these bots produce is a Discovery lead: map-finder links, parking-explorer layers, camp-probe layers, near misses, closure sources from the worksheets, Watcher 'new rules document' hits. They should all write to `data/discovery/leads.json` with the Discovery grade fields (source tier, publisher, keyword, first/last seen, graded by / when) and stop writing their own files; the observations log keeps only OBSERVATIONS (something we show changed) and the Discovery list keeps LEADS (something we might start reading). One review file (the Discovery review md) replaces access-leads.md and the review tabs.
- **Keywords:** the parking explorer's name list, the camp walker's name list, the map finder's link-name list and the Watcher's KEYLINE are four keyword lists today. One `keywords.json` with sections (outlines, access, camps, maps, closures, rules) feeds all of them and the Discovery Bot; a miss Brandon finds by hand goes in once.
- **Testers:** the Discovery design reuses 'the three lead testers'. The link checker (kpc_map_linkcheck) is a fourth: a graded-A map lead is only used after it loads.
- **Schedule:** Discovery monthly inside the boundary check; the data bots keep their own cadence but read the SAME layer lists (state-gis.json, access-layers.json, campstate sources) that Discovery grows. Nothing new to schedule.

## 3. Accurate and fresher with the least work
- **Dates on every fact (one helper):** `kpc_save.py` already strips 'updated'; add `stamp(record, read=YYYY-MM-DD, src=…)` and have each bot write `read` + `src` per park / point / camp / link, the way outlines now do. Tools show 'from <agency>, <date>'; after 12 months 'last read <date>: check'. Small, mechanical, and it makes the Watcher's job possible.
- **Change detection in one place:** a tiny `kpc_changes.py` that every bot calls before save: old vs new per key, writes 'changed / gone / new' counts and samples to the observations log (the 'outline size' code generalised). Then 'kept last good' gets a clock (kept since <date>; over 60 days = observation 'feed stale'), and an empty feed that was not empty last month is an observation, not silence.
- **Official sources only, enforced by publisher:** campgrounds and access points take a layer only when its host is in data/state-gis.json roots or access-layers.json (the agency), or its AGOL owner is on the agency allow list (G-M4 list). An AGOL keyword hit from an unknown owner is a Discovery lead, never data. That alone removes the Arizona Army camps.
- **Hours / fees: read, don't scrape.** NPS API `parks` endpoint gives operatingHours + entranceFees for every NPS unit (key already in secrets; link_harvest calls that API today): one function, dated. State parks: only where the state publishes a reservations / facilities API or GIS attribute (several campstate layers carry FEE / HOURS fields already); otherwise 'not given: check the park page' stays. Kentucky: the Watcher's changed lines go to chat 8 WITH the park ref and the current hand value, so the fix is a one-line edit.
- **Closures: watch the pages too.** The 126 non-feed sources from Round 4 become Watcher targets (hash of the alerts section only), reported as 'closure page changed' with the link; the feed bots stay the only ones that write items. Empty feed ≠ ok: record `n_prev` and flag 'went from N to 0'.
- **Map links: re-find before you drop.** A 404 link whose park has an official page goes back through the map finder once; a 403 is tested with a browser-like GET and marked 'blocked (opens in a browser)' and shown with that word.

## 4. Better worksheets for the outside agents (so results need less checking)
Today's sheets (Round 4 closures, 12 park maps) ask free text: 'Official map link (YOU)', 'Status (YOU)', 'Notes'. Half the checking work is reading the free text. Make every YOU column closed where it can be:
- **A fixed STATUS list** per sheet: FOUND-OFFICIAL / FOUND-UNOFFICIAL / NONE-ON-AGENCY-SITE / BLOCKED / NOT-SURE (drop-down; Brandon's own rule for Google Forms).
- **Two links, not one:** 'Agency page where you found it' AND 'The link itself'. A link with no agency page it came from is NOT-SURE by rule (the publisher test).
- **Publisher column (drop-down):** the agency / the state GIS office / third party, with the domain auto-filled from the link so it can be machine-checked against the allow list.
- **Date seen on the page** (the map's own date or 'none shown') and **what it is** (PDF map / web map / brochure / GIS service) as drop-downs; the Round 12 sheet had these as free text and they came back in 20 spellings.
- **Proof row:** for every FOUND, one quoted line from the page (title or caption) so a checker can confirm without opening it.
- **Machine check column (ours, pre-filled on return):** link loads (yes/no/403), domain on the allow list (yes/no), matches a layer we already read (yes/no). The agent never fills it; the checker only reads rows where a machine check failed.
- **One sheet shape for every round** (Instructions / Summary / Rows), the same column order, so the return can be imported by a script into `data/discovery/leads.json` with grade 'agent-found, unchecked' and go through the normal grading, instead of a per-round hand read.
